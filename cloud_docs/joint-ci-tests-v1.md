# 联合 CI 测试与验收草案 v1

日期：2026-09-23。关联：[设计草案](joint-ci-design-v1.md)。本文件规定未来测试，不包含本轮执行结果。

## 1. 从不变量组织验收

历史 120 用例保留原 ID，但不再以“120 全跑完”代替验收。先建立需求 → 场景 → 断言 → 原始证据映射；没有源码和用例定义的历史条目暂不映射。本次新增 JC-* 为规格 ID，不声称已有对应脚本。

| 不变量 | 必须观察到的事实 |
|---|---|
| 不漏测 | 实际必需任务集合覆盖每仓路由展开的任务；参数变化不会误合并 |
| 不重复消耗 | 同 attempt/task 的重任务准入数 ≤ 1；不只统计 dispatch 调用次数 |
| 不误放行 | 任一缺失、失败、身份不符证据都不能得到 merge_ready |
| 不复活 | 已取消/过期尝试的普通回报不能改变当前结果或启动重任务 |
| 能恢复 | 进程/网络恢复后，在明确时间预算内收敛或报告 blocker |
| 不泄漏资源 | 等待无测试资源；取消/结束后 owned 进程/Pod 回到基线 |
| 可复算 | 每个结论对应同一候选版本、尝试和可读取原始证据 |

## 2. 分层运行，成本逐级增加

| 层 | 环境与入口 | 证明范围 | 出口 |
|---|---|---|---|
| L0 | 本机纯逻辑/解析/路由对照 | 快照规范化、清单并集、门禁真值表 | 确定性用例通过；缺失配置明确 |
| L1 | 真协调器 + fake GitHub + 真实存储适配器 | 事件乱序、崩溃、竞争、恢复协议 | 核心不变量及故障注入通过 |
| L2 | 隔离 GitHub 仓 + self-hosted runner | 真实 API/事件/检查来源/分支保护 | 必需门禁真实拦截；重任务准入真实去重 |
| L3 | 隔离真实 runner/容器/Pod | 启停、断联、子进程、清理 | 资源身份及清理证据闭环 |
| L4 | 生产只读路由对照或经授权 shadow | 路由不漏项、输入映射、现有规则兼容 | 才能评估后台自动灰度 |

不使用 `ubuntu-latest`。L2/L3 执行前运行闭包审计：唯一 validation_context.json 记录源码 tree、入口、参数、配置优先级、依赖、权限、环境变量名称、镜像、挂载、资源配额、成功标志、清理与成本。必需信息 missing 时不运行昂贵测试。

`JOINT_CI_JOBS=6` 仅为历史建议，不等于实际有六个 runner。先测单任务 CPU/内存/资源峰值，再按容量决定并发。测试调度进程不占住唯一 worker 等待子任务。

## 3. 核心场景矩阵

P0：开启生产去重前必须关闭。P1：相应功能启用前完成。层号表示最低证据层；L1 不替代 L2/L3。

| ID | 级别/层 | 前置与操作 | 核心断言及证据 |
|---|---|---|---|
| JC-01 | P0/L1+L3 | 缺一个已声明成员；延迟后补齐 | 等待期重任务/Pod=0；补齐自动派发；持久状态与资源清单 |
| JC-02 | P0/L1 | 成员齐备，Draft、私有 pending | 公共任务可启动；merge_ready=false；记录两种判断输入 |
| JC-03 | P0/L1 | 公共成功后私有检查完成，仅投递检查事件 | 自动转为 ready；公共执行计数不增加；不用人工 reconcile |
| JC-04 | P0/L0+L2 | 每仓私有 success/failure/pending/missing；真实规则要求该项 | failure/missing 不放行；L2 验证非 bypass 身份确实不能合入 |
| JC-05 | P0/L0 | 两仓同名 suite，卡数/参数/环境不同 | 不误去重；完全一致输入才合并；比较完整任务集合 |
| JC-06 | P0/L0 | 仅 JSON 顺序、集合顺序不同 | snapshot/task 身份一致；语义字段变化则身份改变 |
| JC-07 | P0/L1+L2 | 四仓齐备与缺 Sim 两组；再测两 PR+固定依赖 | 四仓实验缺 Sim 不成功；普通两 PR 模式不强求四 PR |
| JC-08 | P0/L1+L2 | 首次登记用 barrier 同时提交两个请求 | 唯一权威组记录；每 task 只有一次实际重任务准入 |
| JC-09 | P0/L1+L2 | 重复 webhook、重复 dispatch、乱序到达 | 可有多个轻量入口，重任务只能有一个 owner；保留 run/owner 轨迹 |
| JC-10 | P0/L1+L2 | 服务器接受 dispatch 后丢弃响应 | 最终找到/认领同一任务；不能仅看客户端异常就重复耗资源 |
| JC-11 | P0/L1 | 在状态提交、意图落盘、dispatch、认领、回报各边界杀进程 | 恢复后不丢任务、不重复执行；每个故障点均有原始状态 |
| JC-12 | P0/L1 | 两 writer 同版本更新；人为制造真实 CAS 冲突 | 至少一次冲突；失败方重读重试；最终状态无覆盖丢失 |
| JC-13 | P0/L1+L2 | B 更新，A SHA 不变；B 事件延迟 | A 旧成功失效；测量传播窗口，明确人工合入残余风险 |
| JC-14 | P0/L1 | 只改变 base、镜像 digest、Arsenal 测试版本之一 | 每个变化独立导致身份失效；不能只检测 head |
| JC-15 | P0/L1 | report 使用旧 SHA/group/generation/attempt/run | 拒绝或审计为 stale；当前状态和检查不受污染 |
| JC-16 | P0/L1+L3 | 测试中取消，一条 lane 已成功 | 立即禁止成功；全部 owned worker 最终清理；取消不能汇总成功 |
| JC-17 | P0/L1+L2 | writer 读完当前状态后暂停，取消提交后释放 writer | 内部旧写入被拒；远端迟到写如发生须修正并记录窗口，不能宣称原子写回 |
| JC-18 | P0/L1 | 取消后并发重复 report，再显式 retry，再旧回报 | report 不复活；retry 仅新 attempt；旧回报不能污染新结果 |
| JC-19 | P0/L1+L3 | 执行者断网但重任务仍活着，租约过期 | 不自动双开；确认旧资源退出前 blocked；记录资源身份 |
| JC-20 | P0/L1 | 丢弃一次成员/私有完成事件；重启协调器 | 短补偿任务自动恢复；既不永远 pending，也不靠人工脚本变绿 |
| JC-21 | P0/L1+L2 | API 429/5xx、超时、403、404、分页 | 有界退避；不可重试错误明确 blocker；分页不漏成员/检查 |
| JC-22 | P0/L1 | 迁组/退出/关闭/重开 PR | 旧组撤销该成员资格；新组不继承旧 success；消费者映射正确 |
| JC-23 | P0/L1+L2 | 伪造 success payload/错 workflow/错 App/错 SHA | 汇总器独立查询可信来源；伪造不能满足门禁 |
| JC-24 | P0/L1+L2 | 必需 job skipped/neutral、workflow success 但缺 lane | 仅外层 success 不足；实际必需任务集合完整才通过 |
| JC-25 | P0/L1 | artifact 缺失/过期/损坏/来自旧 attempt | 禁止复用；默认整轮重试；保留能力未实现记录 |
| JC-26 | P0/L1 | 请求只重跑失败 job，而第一版未支持 | 明确拒绝或转完整新尝试；完整 required 集合不能被缩小 |
| JC-27 | P0/L0+L1 | 独立模型与 SUT 接收同一随机操作序列 | 每一步对比状态/派发/attempt/成员/快照/取消/门禁/blocker；保存首个 divergence |
| JC-28 | P0/L1+L3 | 多 group，worker=1/2/容量允许值；制造饱和 | 记录实际并发、排队、重复重任务数、丢组数、排空时间、资源清理 |
| JC-29 | P0/L2 | 改 required check 来源；同名错误 App 写 success | 保护规则拒绝错误来源；正常来源通过；记录规则与真实合入拒绝 |
| JC-30 | P0/L2 | 人工合入第一笔，再更新第二笔或其 base | partial_merge 明确；旧证据不能复用；第二笔重新验证；不自动回滚第一笔 |
| JC-31 | P1/L2 | 两个 PR 使用同一 head，或启用 merge queue | 验证检查作用域；不支持则明确拒绝该模式，不悄悄复用 |
| JC-32 | P0/L0+L4 | 普通 PR 与联合 PR 的相同改动清单 | 普通路由不变；联合展开集合等于旧路由需求并集，无静默遗漏 |
| JC-33 | P0/L2+L3 | 关闭联合开关；在途任务运行中 | 撤销旧资格、清理资源、恢复原 CI，原检查完成前不放行 |
| JC-34 | P0/L1 | 包中混旧 CSV、删 raw、改 hash、改统计 | 交付校验失败且指出具体文件/记录；不能自动修成通过 |
| JC-35 | P0/L0+L1 | 故意移除取消判断、少算 Sim、接收旧 attempt | 对应用例必然失败；证明断言能检出目标缺陷 |
| JC-36 | P0/L0+L2 | 原样重放历史 PR 正文与提交顺序；不增加任何字段/标签 | 原操作可完成；自动解析、触发、结果回写；用户新增必需操作数=0 |
| JC-37 | P0/L0+L2 | 唯一显式依赖、默认分支、固定 tag/SHA、fork 同名、多 PR、冲突组合 | 符合安全规则才关联；其他保留旧测试语义；不能猜组或扩大依赖 |
| JC-38 | P0/L1+L2 | 分支先存在而 PR 几天后出现；第一笔完全无依赖声明 | 不为等未知 PR 占资源或阻塞原流程；只有相同输入可复用；统计实际重复成本 |
| JC-39 | P0/L2 | 从每个 PR 原有入口点击 Re-run jobs 和 Re-run failed jobs | 用户无需新命令；正确生成一次新 attempt；未支持部分重跑时明确全套重试 |
| JC-40 | P0/L1+L2+L3 | A 取消，B 仍订阅；再取消 B；A 单独重跑 | A 不被 B 的成功复活；B 的任务不被误杀；无人订阅才清理；重跑身份正确 |
| JC-41 | P0/L1+L2 | 自动灰度未命中、关联歧义、调度故障发生于准入前后 | 可安全退回旧路由；不能共享与旧路径双跑；状态未知明确阻塞 |
| JC-42 | P0/L2 | 用原 PR Checks 页面定位 pending、失败、日志与重跑 | 不要求跳到组 Issue/控制仓输入命令；明确哪个测试/依赖在等待 |
| JC-43 | P0/L0+L2 | 单向引用使被引用 PR 默认测试输入与联合快照不同 | 不强行换掉被引用 PR 的输入；保持原测试或按后台已证明规则共享 |
| JC-44 | P0/L2 | PR 已取消后重复原事件，再推新 commit | 旧尝试不复活；新提交按原 CI 触发习惯进入新 generation |

## 4. 少量确定性竞态优先于长时间随机跑

取消示例必须控制交错，而不是依赖 sleep 碰运气：

```text
1. writer 读取 generation=7 / running 后，在测试 barrier 停住。
2. canceller 持久化取消标记并撤销 attempt=2 的写入资格。
3. 释放 writer，让其提交先前计算的 success。
4. 验证内部条件更新拒绝旧写；检查远端发布是否存在迟到窗口。
5. 等待修正和资源清理，核验最终检查与资源都收敛。
```

同样控制：首次登记、dispatch 响应丢失、状态提交后崩溃、私有完成与换代交错。每个案例保存 barrier 时间与版本，不以“调用了两次”证明竞争成立。

随机测试使用预先冻结的 seed 列表和操作数量；保存完整 trace，失败序列最小化后加入回归。独立模型不导入 SUT 的状态转换/门禁判定函数，不能由 harness 写死 expected pass。

## 5. 执行前冻结与恢复

每轮冻结：SUT tree digest（含未提交修改）、harness/oracle digest、配置 digest、依赖版本、suite 清单、场景模板版本、环境信息。用真实提交身份与合成输入身份分别标注，40 位 hex 合法不等于真实 checkout。

故障注入用例需要多份快照，不能要求整个 suite 永远使用同一个 snapshot。正确要求是：固定该轮基线和场景定义，每个 case 保存全部生成快照与转换；只复用身份完全一致的该 case 结果。

修改代码或断言后开新 candidate/run_id，建立父子关系；不得在旧 run_id 中混入新代码结果。可只重跑受影响用例，但报告必须列明其他结果来自哪一候选版本以及复用理由。最终版本尚未重跑的关键项不得冒充当前版本 PASS。

安全停止仅作用于本轮拥有的进程/资源，先留 checkpoint 和日志。每 case 独立超时；超时继续后续案例，但不把未评估当失败行为已验收。

## 6. 结果与证据契约

推荐分开记录运行状态和验收结论，避免 BLOCKED 被折算成 PASS：

| 字段 | 值 |
|---|---|
| execution_status | COMPLETED / BLOCKED / SETUP_FAILED / NOT_RUN |
| verdict | PASS / FAIL / NOT_EVALUATED |
| evidence_class | MODEL / LOCAL_REAL_SUT / REAL_GITHUB / REAL_RUNTIME / SHADOW |

只有场景已建立、指定操作实际执行、断言有效且证据完整才可 PASS。明确观察到不变量破坏记 FAIL；环境无法建立则未评估并写原因。统计提供互斥 verdict 总计，同时保留 execution_status 分布。

每条记录包括 case_id、requirement_ids、candidate_id、suite_run_id、case_attempt、seed、group/generation、snapshot_ids、task/attempt/run/job 身份、版本摘要、故障注入点、原始证据路径、断言结果、时间和清理结果。

```text
run/
  identity.json          # 代码、工具、环境与场景基线
  suite-manifest.json    # 本轮所有 case；必需与范围后置项显式区分
  cases/<id>/<attempt>/  # inputs、events、states、observations、assertions、raw
  results-all.csv        # 唯一 canonical 结果索引
  summary.json
  TEST_REPORT.md
  recompute/             # 原始证据独立判定差异 + 汇总统计差异
  limitations.md
  file-manifest.sha256
```

两种复算都需要：A 从 CSV 核对统计；B 使用独立判定逻辑从原始 observation 复核关键断言。A 的 mismatch=0 不能替代 B，也不能替代“测试设计有效”。

manifest 覆盖交付文件但排除自身及外部 archive；archive 完成后生成旁路 sha256，避免自引用 hash。重新解包到隔离目录验证文件路径、完整性、统计、原始证据、版本归属及敏感信息。源码与原始证据必须足以重放，不能只交报告。

## 7. 通过标准与时间预算

先用 JC-36/37/43 建立旧操作和依赖解析基线，再跑 JC-02/03/05/08/10/16/18/24/35 最小核心集，随后推进 L1 全部 P0，最后才申请 L2/L3 资源。历史 120 用例映射到这些需求后纳入，不重复堆叠等价测试。

用户体验硬门禁：原样 PR 模板/正文可用；新增必需操作数为 0；原查看、取消、重跑入口可用；无须同时提 PR；未命中自动关联时原 CI 可继续。后台另行记录可关联比例、实际重任务节省量、误关联数、fallback 比例及新增等待时间。首批目标值由历史 PR 对照确定；误关联必须为 0，不能以节省量掩盖行为变化。

在执行清单中冻结：T_dispatch、T_reconcile、T_cancel_cleanup、T_drain 及最大重试数。数值由预检的容量和 API 限流基线确定，执行后不得为了通过而放宽；本轮没有运行数据，因此不编造固定 SLA。

| 阶段结论 | 必须满足 |
|---|---|
| 本地协议通过 | L0/L1 必需 P0 全部真实 PASS，断言变异测试有效，独立证据复算无差异 |
| GitHub 集成通过 | L2 指定 P0 通过；真实门禁、来源绑定、失效传播与残余窗口记录完整 |
| 运行层通过 | L3 清理、断联、准入与容量通过；没有永远 pending 或遗留资源 |
| 可试点 | 路由并集无遗漏；上述所需层与用户体验门禁已通过；回滚可验证；人工合入边界被接受 |

安全不变量采用零容忍：误放行、旧结果污染、取消复活、同 attempt 重任务双开任一出现都阻断相应阶段。吞吐与延迟按已冻结预算验收，不能宣称有限随机测试证明所有交错永远安全。
